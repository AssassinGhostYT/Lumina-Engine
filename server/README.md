# Lumina Engine Remote server

A tiny Cloudflare Worker that lets an AI (Claude, OpenCode or any MCP client) control the Lumina Engine editor running on a phone. The phone connects *out* to this server with a WebSocket; the AI calls tools over MCP; the server relays each call to the phone and returns the answer. Nothing runs on the server except the relay.

```
AI client ──MCP (HTTPS)──▶ Worker ──RPC──▶ Durable Object (one per user) ◀──WebSocket── Lumina Engine app
                        /mcp/<secret>                          /ws/<secret>
```

## Deploy (free plan is enough)

```bash
cd server
npm install
npx wrangler login          # once
npx wrangler deploy         # prints https://lumina-remote.<you>.workers.dev
```

Then in the Lumina Engine app: open **AI remote control** (the Claude/remote icon) → paste the `https://....workers.dev` URL in **Server URL** → **Save** → turn the switch on. The app shows the private connector link (`https://<server>/v1/mcp/<secret>`).

* **Claude:** Settings → Connectors → Add custom connector → paste the link (no login). **Copy command for Claude** gives you the text to paste into a chat.
* **OpenCode:** press **Copy OpenCode MCP config** and paste it into `opencode.json` (see below).
* **Any other AI:** **Copy command for another AI** gives a plain-HTTP fallback.

The app ships with **no default server** on purpose: each person deploys their own free Worker, so nobody depends on somebody else's quota. To ship a default for everyone who installs your build, set `DEFAULT_SERVER` in `RemoteSettings.java` before building.

## Connect OpenCode (free Zen models)

OpenCode is the recommended way to get free/cheap AI control, because its free Zen models work **inside OpenCode** (the direct API does not allow them). In the app press **Copy OpenCode MCP config**, then put the block in the project's `opencode.json` or in `~/.config/opencode/opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "lumina": {
      "type": "remote",
      "url": "https://<your-worker>.workers.dev/v1/mcp/<secret>",
      "enabled": true
    }
  }
}
```

Start OpenCode with `opencode`, run `/connect` (OpenCode Zen) or `opencode auth login`, then `/models` and pick a **FREE** model (Big Pickle, DeepSeek V4.1 Flash Free, GLM-5.3-Flash Free...). Keep the Lumina editor open and ask it to build or edit the game; it uses the same tools Claude uses.

> The secret in the URL is the only credential. Anyone with the link can control the editor, so keep `opencode.json` private.

## Endpoints

| Path | Who | What |
| --- | --- | --- |
| `POST /mcp/<secret>` | the AI | MCP Streamable HTTP (JSON-RPC, JSON responses) |
| `POST /api/<secret>/<tool>` | an AI without MCP | same tools, arguments as the JSON body |
| `GET /ws/<secret>` | the phone | WebSocket (hibernating) |
| `GET /AI.md` | any AI | short guide: "use this link to understand my project" |
| `GET /health` | you | `ok` |

The secret (24–128 chars of `A-Za-z0-9_-`) is generated by the app and is the only credential. Treat the connector URL like a password; the app can generate a new one.

## Cost on the Cloudflare free plan

Limits are per Cloudflare **account** (shared by everyone using your deployed server): 100,000 Worker requests/day, 100,000 Durable Object requests/day, 13,000 GB-s DO duration/day, 100,000 SQLite rows written/day.

* A tool call = 1 Worker request + 1 DO request. `initialize`/`tools/list` are Worker-only (no DO).
* The phone's socket uses WebSocket Hibernation: no duration is billed while idle. Incoming messages from the phone count 20:1; outgoing are free; protocol-level pings are free.
* `wait_for_app` holds the object up to 25 s per call (that is the only duration you pay).
* The tools are batch tools (`elements`, `events`, `files`...) so a whole game is hundreds of calls, not tens of thousands.
* `DAILY_CALLS` (default 4000, in `wrangler.toml`) caps the calls one secret can make per day, so one runaway client cannot eat the account's budget.

## What the server stores, and cleanup

Almost nothing: a small `meta` record (last connection time) and `usage:<YYYY-MM-DD>` counters per user. No project files, no screenshots (images are relayed, never stored).

* When any phone connects, counters of earlier days are deleted ("old folders").
* When the phone disconnects, an alarm is set for `IDLE_PURGE_HOURS` (default 24). If the user did not come back, **everything** of that user is deleted.

## Develop / test

```bash
npm run typecheck
npm test            # starts wrangler dev --local, connects a fake phone, drives it through MCP (17 checks)
```

`src/tools.ts` is the tool catalog (what the AI sees). The implementations live in the app: `app/src/main/java/com/lumina/engine/remote/`. Keep both in sync when adding a tool.

## API versions

The server serves every API version side by side: `/v1/mcp/<secret>`, `/v1/api/<secret>/<tool>`, `/v1/ws/<secret>`, `/v1/AI.md`.
`GET /version` lists the versions it supports (`{"versions":[1],"latest":1}`); the app reads it before connecting and shows
"The server needs an update" when its own version is missing. The old unversioned paths (`/mcp`, `/api`, `/ws`, `/AI.md`) are aliases of v1.

To release v2: write `handleV2` in `src/index.ts`, add it to `HANDLERS` and `SUPPORTED`, and raise `API_VERSION` in the app's `RemoteSettings`. Never change what v1 does.
